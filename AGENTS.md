# shelld Development Guide

## Project Context

- 利用方法は [README.md](README.md)、構造と前提は [project overview](docs/chatgpt-project/00_PROJECT_OVERVIEW.md) を読む。
- 現行対象は Arch Linux の Bash / Zsh。Mac対応の要件・受入状態は Beads で確認し、未実装を対応済みと扱わない。
- `make apply-*` はログインシェルと HOME の rc を変更する。検証は隔離した HOME とコマンドの mock を使い、実ユーザー設定へ適用しない。
- `common/` は両シェルが読み込む。変更箇所と直接影響する Bash / Zsh の経路を確認する。
- `private/` と既存バックアップを読取結果や Git へ混入させない。

## Work And Authority

- material な作業開始時に `bd prime`、`bd ready --json` を確認し、対象の要件を読んで claim する。
- 課題登録だけの依頼では対象の実装を開始・claim しない。
- active state、検証、引継ぎは Beads の構造化 field と comment が正本。別の発見は元課題と関連付ける。
- `.agents/chats/` と `.agents/tasks/` は導入前の履歴として保持し、追記・一括移行しない。
- stable な仕様は文書へ同期し、ChatGPT用文書に進捗や未完了項目の一覧を複製しない。
- repository write は local `master` 起点の専用 branch / 外部 worktree で行う。primary は `master` 固定の統合用とする。
- Beads の DB は primary に共有される。tool生成物の初期配置例外はユーザーが許可した今回の初期化だけで、一般的な primary 編集許可ではない。
- commit、merge、push、Dolt同期の権限はユーザー指示と共通 workflow に従う。claim / close から権限を推定しない。
- 検証済み項目だけ close する。未検証の条件は具体的な次の確認とともに課題へ残す。

## Validation

- 変更した挙動と直接関係する caller / contract に絞って検証する。
- 文書のみの変更は link、sourceとの整合、`git diff --check` を確認する。
- Beads連携は生成済み skill、`bd prime` と現在の CLI を command-level の正本とする。
- 実行できない検証は、成功扱いせず理由と範囲を記録する。

## Beads Issue Tracker

Use Beads (`bd`) for durable task tracking in repositories that include it. Use the `beads` skill at `.agents/skills/beads/SKILL.md` (project install) or `~/.agents/skills/beads/SKILL.md` (global install) for Beads workflow guidance, then use the `bd` CLI for issue operations.

### Quick Reference

```bash
bd ready                # Find available work
bd show <id>            # View issue details
bd update <id> --claim  # Claim work
bd close <id>           # Complete work
bd prime                # Refresh Beads context
```

### Rules

- Use `bd` for all task tracking; do not create markdown TODO lists.
- Run `bd prime` when Beads context is missing or stale. Codex 0.129.0+ can load Beads context automatically through native hooks; use `/hooks` to inspect or toggle them.
- Keep persistent project memory in Beads via `bd remember`; do not create ad hoc memory files.

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md for details and anti-patterns.
